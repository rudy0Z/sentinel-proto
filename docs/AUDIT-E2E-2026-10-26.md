FireTracer is a **frame-accurate after-incident reviewer**: timestamped event ledger down the side, playback scrubber with speed control, live telemetry HUD (ALT/SPD/BATT readouts), sensor charts over time, annotated evidence frames, map track replay.

| FireTracer capability | Sentinel today | Gap |

## 5. The UI reference collection — what quality is missing

The references are dense **mission-control panels**: tabular telemetry rows, layered status cards with legends, sparklines inline in rows, structural grids — information-dense but disciplined. Compared to them:

1. **Tabular density.** Our widgets are card-led; references lean on *tables with inline status*. The fleet widget is close; weather/evac are chunkier than the references' row-metaphor. Medium effort, real polish.
2. **Inline sparklines.** References put a 60×20 trend inside list rows (per-unit battery trend, per-zone clearance rate). We have one big growth chart. A `Sparkline` primitive would lift the whole board. Small effort, visible payoff.
3. **Micro-legends.** References annotate every color/line convention on-surface. We have it in the layers popover only. A one-line legend strip on the growth widget (burned / +30 / +60) would match. Small.
4. **Depth via typography.** References use weight+size steps aggressively within one card. We have the scale; the widgets under-use it (everything caption-size). Small.

**None of these are "half-baked" markers — they're the last 15% of density craft.**
