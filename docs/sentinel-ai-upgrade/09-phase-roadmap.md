# 09 - Phase Roadmap

This roadmap turns the product decisions into implementation phases. It is written so execution can happen without losing the strategic intent.

## Phase 0 - Documentation Archive

### Intent

Preserve all product decisions before changing the prototype.

### Work

- Create `docs/sentinel-ai-upgrade/`.
- Save previous plan.
- Document breakthrough decision.
- Document real-world grounding.
- Document product thesis.
- Document TALON workflow.
- Document data visualization system.
- Document governance and auditability.
- Create implementation log and decision-story archive.

### Acceptance Criteria

- Documentation archive exists.
- Previous plan saved.
- Product shift is explicit.
- Implementation can start from written context.

## Phase 1 - Visible Two-Phase Product Model

### Intent

Replace four visible phases with Intelligence / Operations.

### Work

- Add visible workflow phase model.
- Change nav phase labels.
- Change guidance strip.
- Change review dock grouping.
- Change copy from Scan/Verify/Contain/Rescue to Intelligence/Operations where user-facing.
- Move 90-second endpoint to authority notification.

### Acceptance Criteria

- User-facing product no longer feels like four separate phases.
- Intelligence ends at authority notification.
- Operations begins after notification.
- Existing scene functionality still works.

## Phase 2 - Intelligence Workflow

### Intent

Make the first 90 seconds data-rich and AI-visible.

### Work

- Add structured evidence sources.
- Add confidence convergence timeline.
- Add source matrix.
- Add TALON working states.
- Add authority notification packet.
- Add Intelligence decision gate.

### Acceptance Criteria

- Operator sees TALON gathering and synthesizing evidence.
- Operator sees missing data.
- Operator sees why escalation is recommended.
- Notification packet can be marked ready and sent.

## Phase 3 - Operations Workflow

### Intent

Move containment/rescue planning after notification and make it more credible.

### Work

- Add operations brief.
- Add containment options.
- Add rescue zones.
- Add route viability.
- Add drone/team assignment visuals.
- Add operations authorization gates.

### Acceptance Criteria

- Operations clearly starts after authority notification.
- TALON prepares but does not authorize.
- Field planning feels complex, visual, and data-driven.

## Phase 4 - TALON Copilot Rail

### Intent

Make TALON feel like a copilot rather than static recommendation copy.

### Work

- Replace right rail.
- Add TALON status module.
- Add evidence convergence module.
- Add agent task module.
- Add conversational prompt chips.
- Add recommendation and missing-data module.
- Add decision receipt preview.

### Acceptance Criteria

- TALON is persistent.
- TALON answers contextual questions.
- TALON shows what it knows and does not know.
- TALON never claims unauthorized control.

## Phase 5 - Data Visualization Upgrade

### Intent

Replace text-heavy panels with visual data systems.

### Work

- Redesign left rail as selected-data inspector.
- Add risk vector strips.
- Add source chips.
- Add sparklines/charts.
- Add stronger map overlays.
- Reduce long paragraphs.

### Acceptance Criteria

- The UI feels data-driven.
- The operator can scan status quickly.
- Visual data does most of the communication.

## Phase 6 - Agentic Workflow

### Intent

Show TALON working as supervised agents.

### Work

- Add TALON agent task model.
- Add Sensor Fusion, Fire Behavior, Values at Risk, Resource Readiness, Notification Brief, Operations Planner, Governance tasks.
- Add task statuses.
- Add blocker and human gate states.

### Acceptance Criteria

- AI work is visible.
- Agent tasks show progress and blockers.
- Agent outputs link to evidence or decisions.

## Phase 7 - Governance And Audit

### Intent

Make accountability visible and case-study-ready.

### Work

- Add decision receipts.
- Add authority notification receipt.
- Add override receipt.
- Add operations authorization receipt.
- Add exception acknowledgement receipt.
- Add closure receipt.

### Acceptance Criteria

- Major actions create receipts.
- Receipts show source state and human action.
- Audit trail is credible for enterprise AI.

## Phase 8 - Failure Simulation Suite

### Intent

Make failure states a first-class part of the AI product.

### Work

- Add Intelligence failures.
- Add Operations failures.
- Add degraded source visuals.
- Add human-gate fallback paths.
- Add audit records for failure handling.

### Acceptance Criteria

- Every failure state has trigger, affected data, TALON behavior, recovery, and accountability.
- Failure states strengthen the product story.

## Phase 9 - Microinteraction And Visual Polish

### Intent

Make the prototype feel like a 2026 AI product.

### Work

- Add evidence transitions.
- Add TALON processing animation.
- Add source chip transitions.
- Add agent task progress motion.
- Add map layer fades.
- Add conversation streaming simulation.
- Add reduced-motion alternatives.

### Acceptance Criteria

- Product feels alive but not decorative.
- Motion clarifies state.
- Data changes are easier to perceive.

## Phase 10 - Case Study Evidence Prep

### Intent

Prepare final case-study rewrite after product upgrade.

### Work

- Capture screenshots.
- Capture video walkthrough.
- Update decision stories.
- Mark unsupported old claims.
- Prepare final 2026 case-study outline.

### Acceptance Criteria

- Case study can be rewritten from documented decisions and product evidence.
