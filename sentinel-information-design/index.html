0.1 Purpose

FlytBase Sentinel's thesis is that wildfire first-response is not a hardware problem but a cognitive-friction problem: the traditional detection-to-response chain runs ≈48 minutes (challenge-brief anchor), dominated by slow verification, verbal dispatch, and travel-blind size-up, while the 90-second design target compresses detection→validated alert→tasking decision into a single continuous operator arc (0–15 s fuse, 15–45 s VERIFY, 45–75 s CONTAIN, 75–90 s RESCUE). This package is the information-design research behind that redesign: what data exists and when it arrives (01), what TALON consumes and may propose (02), what the operator must decide and under what authority (03), what the fleet physically provides and at what bandwidth (04), where the 48 minutes actually goes (05), where the current repo UI falls short (06), the component-level interface specification (07), how every UI element traces to the 90-second KPI (08), how the interface behaves when things fail (09), and the raw research index (10). It is a research-and-spec deliverable — no production code changes were made.

0.3 KPI anchor & honesty note

  • KPI anchor: 48 min → 90 s. Both figures come from the challenge brief (src/imports/FlytBase_Sentinel_Project_Brief_Con.txt; PRODUCT.md states plainly: "the 48-minute baseline and 90-second target come from the challenge brief, not a field study") [repo].
  • No public dataset decomposes an end-to-end wildland 48-min figure; the segment allocation in chapter 05 is a constructed allocation calibrated to the anchor, with NFPA 1710 urban floors used as anchors (they are structural-fire benchmarks, not wildland measurements) [R1].
  • The 90-s target scopes detection → validated alert → tasking decision — not water-on-fire. Crew travel is not compressible by information systems [R1]. Sentinel moves information, not apparatus.
  • Counterweight retained: reporting-delay improvements alone yield ≈0.25 % suppression-cost savings [R1 · Huang 2024] — the honest claim is time-to-defensible-decision, biggest on the fast-growing-ignition tail, not the median fire.
  • All chapters mark estimates [est], inferences [INF], and source tags [S#]/[repo] per the methodology rules in 10-research-appendix.md §10.3.

The package is built to be walked in one direction:

03 decisions  →  07 components  →  08 KPI rows
(every operator decision maps to a component; every component row maps to a KPI moment in the 90-s arc)
  • Chapter 03 defines each operator decision (authority tier, data required, timing window).
  • Chapter 07 specifies the UI component that carries each decision (panel slot, data fields, states) — panel slots follow the repo's layout engine (src/app/domain/panels.ts) [repo].
  • Chapter 08 traces each component row to the KPI: which seconds of the 0–15/15–45/45–75/75–90 arc it serves, and which 48-min traditional segment it compresses (from chapter 05).
  • Chapter 09 is the failure-side mirror of the same chain: every risk row names its phase (F/V/C/R/OPS), its early UI indicator, and its interface mitigation.
  • Every claim is traceable backward: chapter figure → [repo] tag (→ repo-audit.md §/path) or [R1]–[R4] tag (→ research/*.md → 10-research-appendix.md §10.1).

Honesty note — read before using any number below

The 48-minute end-to-end decomposition is a constructed allocation calibrated to the challenge-brief anchor, not a measurement. No public dataset decomposes an end-to-end "detection → effective response" 48-min figure for wildland fire [R1 §e1]. Segment low/high ranges in table (b) were built so the midpoint ≈ 48 min; the NFPA 1710 numbers used as anchors (64–90 s alarm processing, 80 s turnout, 240 s travel) are structural-fire, career-department, 90th-percentile urban floors — wildland interagency dispatch and rural travel run longer [R1 §e4]. Only the structural-dispatch steps and satellite latencies have real sourced anchors; detection-latency distribution, size-up duration (5–15 min), and night/terrain penalties are judgment [R1 §e2, §e3, §e5]. Treat segment shares as design heuristics, not measurements.

Scope note (counterweight): Huang et al. 2024 estimates a 1-hour reporting-delay reduction yields only ≈ 0.25 % suppression-cost savings across all fires [R1 source 25: https://pmc.ncbi.nlm.nih.gov/]. Sentinel's claim therefore targets time-to-decision on the fast-growing-ignition tail — where initial-attack success collapses with response time [R1 sources 23, 24: https://connectsci.au/, https://pubmed.ncbi.nlm.nih.gov/; IA success 83–99% https://www.mdpi.com/] — not average total suppression cost, and not 90-second water-on-fire [R1 §e6]. 1 · Method

The KPI anchor is given by the challenge brief, not re-derived: traditional first-signal → effective response ≈ 48 min, Sentinel target ≈ 90 s [repo·FlytBase_Sentinel_Project_Brief_Con.txt §1]. PRODUCT.md states the provenance plainly: "the 48-minute baseline and 90-second target come from the challenge brief, not a field study." Scope is time-to-defensible-decision — detection → validated alert → tasking decision → supervised execution handoff — not water-on-fire [05 scope note]: crew turnout + travel (11–35 min) is not compressible by information systems [05(c)], and the 90-s clock ends decision-complete, with the operator repositioned at exactly three human gates (verify → authorize → supervise) [05(d)].

The 90-s arc is the repo-canonical handoff [repo·brief §4]: 0–15 s sensor fusion before interrupt (thermal spike 03:47:03 → alert threshold crossed 03:47:18 → nearest drone launches autonomously) → 15–45 s single-question VERIFY → 45–75 s CONTAIN authorize (press-and-hold) → 75–90 s RESCUE exception-only supervision. Arithmetic basis: 48 min = 2880 s; 2880 ÷ 90 = 32 ⇒ ×32 compression. Two honesty rules govern every number below. (a) Constructed allocations: the four segment values (15 + 30 + 30 + 15 = 90 s) are constructed allocations calibrated to the given anchor, exactly as 05(b) constructed the 48-min decomposition — they are design heuristics [est], not measurements. (b) Parallelism: the arc is a pipeline, not a serial sum — elements marked parallel (dock launch 45–60 s, EO/thermal corroboration, projection precompute, audit append) ride inside the windows and are not additive; the only serial sum claimed is the four segment windows. Per-element "seconds saved" columns therefore overlap where several elements compress the same traditional step; only the segment total binds. Range honesty: 05(b) totals run 24–90 min, so the defensible compression ratio is ×16 (favorable 24-min case) to ×60 (unfavorable 90-min case); ×32 uses the 48-min midpoint.
